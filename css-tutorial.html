2. Read your first CSS rule

HTML describes elements. CSS chooses elements and gives them visual properties:

p {
    color: #26332f;
}

p is a selector: it matches every paragraph. Inside the braces is a declaration. color is a property; #26332f is its value, a hexadecimal color. The colon separates the property from its value; the semicolon ends the declaration. CSS comments use /* comment */.

Some selectors already used in your site:

Selector Matches
h1 Every <h1>
.project-item Elements with class="project-item"
#header The element with id="header"
.project-item a Links anywhere inside a project item

A class can label multiple elements. An ID should identify one element on a page. A space between selectors means “inside.”

Append this to styles.css:

/* Tutorial: page foundation */
body {
    background: #f8f7f3;
    color: #26332f;
    font-family: system-ui, sans-serif;
    font-size: 1.0625rem;
    line-height: 1.7;
}

background paints the page. font-family asks for the operating system’s interface font, with a generic sans-serif fallback. rem is a unit relative to the root element’s font size: with the common 16px default, 1.0625rem is 17px. It also respects the reader’s font preferences. Unitless line-height: 1.7 makes each line 1.7 times the text size.

Text properties such as color and font usually inherit: descendants use their parent’s value unless another rule sets their own. Your existing h1 rule sets its own font and color, so we’ll change those explicitly later.

3. Understand the box model and page width

Every element occupies a box. From the inside out, it has content → padding → border → margin. Padding creates room inside the border. Margin separates the box from its neighbors.

Append:

/* Include padding and borders in declared widths. */
*, *::before, *::after {
    box-sizing: border-box;
}

body {
    max-width: 72rem;
    margin: 0 auto;
    padding: 3rem 1.5rem 5rem;
}

body > p {
    max-width: 65ch;
}

img {
    max-width: 100%;
    height: auto;
}

* matches every element. ::before and ::after are generated boxes that CSS can create; including them makes this sizing rule consistent if you use them later.

max-width caps the page width but still allows it to shrink. In margin: 0 auto, the first value sets top/bottom margins to zero and the second splits leftover horizontal space evenly, centering the page. Three-value padding means top, left/right, bottom. These shortened forms are called shorthand properties.

body > p matches only paragraphs directly inside the body; > means “direct child.” This caps your homepage introduction at about 65 characters per line, using ch, the width of the font’s “0” character. Your projects can still use the wider page. It doesn’t cap every nested article paragraph; later you can give article content its own wrapper if you want a separate reading width.

The image rule lets large images shrink with their container while preserving their proportions. Your existing .project-image selector is more specific than img, so its fixed height still wins until lesson 7.

Checkpoint: on a wide screen the page is centered, with breathing room around it. Narrow the browser: the page should shrink without the introduction spilling sideways.

4. Learn the cascade while improving headings

Multiple rules can match the same element. The browser resolves them through the cascade. For the normal rules in your stylesheet, a more specific selector beats a less specific selector. When specificity is equal, the declaration written later wins. Rules combine property by property; a later rule doesn’t erase properties it never mentions.

For example, .project-image is more specific than img. Two h1 rules have equal specificity, so the later one wins for any properties both set. Inheritance supplies a value only when the element has no applicable value of its own.

Append:

h1, h2, h3, h4 {
    color: #183d35;
    font-family: system-ui, sans-serif;
    line-height: 1.2;
}

h1 {
    font-size: clamp(2rem, 5vw, 3.25rem);
    letter-spacing: -0.035em;
    margin: 0 0 1rem;
}

h2 {
    margin-top: 2.5rem;
}

p {
    margin: 0 0 1.25rem;
}

Commas group selectors that share declarations. clamp(minimum, preferred, maximum) makes the heading grow with the browser width while staying between two limits. vw means hundredths of viewport width: 5vw is 5% of the viewport. em is relative to the element’s own font size here, so letter spacing scales with the heading.

Try it: right-click your name, choose Inspect, and find its styles. You should see the old h1 font size crossed out. Temporarily untick the new font size in Developer Tools. These browser experiments are temporary; save permanent changes in the file.

7.2 · Your first rules: give the page room

A CSS rule has a selector followed by declarations inside braces. In body { color: #26332f; }, body chooses the body element, color is a property, and #26332f is its hexadecimal color value. Every element has a box: content inside padding, then a border, then outside margin. * selects every element. box-sizing: border-box makes declared widths include padding and borders, helping boxes fit their assigned space.

The existing HTML groups each project with these labels: .project-item is the outer div, .project-link is its link, .project-image is the image, and .project-title is the heading. A dot in a selector matches a class. Add these rules below the first block:

border combines thickness, line style, and color; a pixel (px) is a CSS length unit. border-radius rounds corners. overflow: hidden clips content that extends outside the card, including image corners. margin-bottom separates the stacked cards. min-width: 0 lets a card shrink below its content’s natural minimum width when we put it in a grid.

We’ll add a clear keyboard focus outline in step 7.5.

For images, width: 100% fills their container. height: auto allows the height to be calculated, while aspect-ratio: 3 / 2 requests a consistent frame that is three units wide for every two high. object-fit: cover fills that frame, cropping edges if the original image has different proportions. Image display: block also removes the baseline gap that inline images can leave beneath them.

The heading’s margin: 0 removes browser-default outside spacing. Its padding creates inside space instead. font-size sets its text size; overflow-wrap: anywhere lets an unusually long word break rather than widen the card.

7.4 · Let the gallery choose its columns

Grid arranges direct children in rows and columns. Start with a single column: append this block, reload, and inspect the Layout panel in Developer Tools.

.project-list {
    display: grid;
    grid-template-columns: 1fr;
    gap: 1.5rem;
}

.project-item { margin-bottom: 0; }

display: grid makes the list a grid container and its project divs grid items. grid-template-columns defines the columns. One 1fr track takes one share of the available space. gap separates rows and columns without adding outside gutters. The later .project-item rule removes the old bottom margin so margin and gap do not both add spacing. With equal selectors in this stylesheet, the later declaration wins for that property.

Try before reading on: replace 1fr with 1fr 1fr. You get two equal columns, even when that is too cramped. Now replace just that columns declaration with:

grid-template-columns: repeat(auto-fit, minmax(min(100%, 18rem), 1fr));

Read the nested functions from the inside out:

  1. min(100%, 18rem) picks the smaller of the container width and 18rem. This lets a column fit on a narrow phone.
  2. minmax(..., 1fr) lets each column grow from that minimum to a share of the available space.
  3. repeat(auto-fit, ...) creates as many of those columns as fit and shares leftover space among them.

7.5 · Show where the keyboard is

:hover, :focus-within, and :focus-visible are state selectors, called pseudo-classes. Hover matches pointer position. Focus-within matches a card when something inside it, such as its link, has focus. Focus-visible lets the browser show an indicator when keyboard focus needs to be visible. Append:

16. Cascade architecture: win without escalating selectors

The project and article pages share styles.css, but the report and Todo pages also set iframe properties in inline style attributes. The exported literature review has inline table-cell styling. Inspect where a value comes from before deciding which file to edit.

Normal inline style attributes outrank normal stylesheet rules. Among ordinary rules in the same origin, importance, and layer, specificity matters before source order. Stylesheet blocks in the HTML still use normal selector specificity; they are not the same as a style="..." attribute.

Optional refactor, not another append-only patch: after saving your baseline, move all existing shared declarations into a named layer and place new component rules in another. The schematic below shows the structure, not a replacement file with every existing rule included.

@layer legacy, components;
@layer legacy {
    /* Move the existing shared declarations here. */
}
@layer components {
    .booktitle { color: #183d35; }
}

For normal author declarations, later layers beat earlier layers before specificity is compared. Unlayered normal rules beat normal layered rules, so simply wrapping new overrides in a layer while leaving the old rules outside it can make your overrides lose. Inline style attributes on the iframes and exported table cells still take precedence over normal stylesheet rules; moving stylesheet rules into layers does not remove those attributes. Important declarations reverse layer priority; avoid using them as a routine repair tool. See MDN’s cascade-layer guide.

20. The final repair expedition

Pick three pages with different jobs: one essay, one visual project, and one page with a reference table or embedded demo. Give them a coherent type scale and palette while preserving what each needs. Then use the complete map below to reach the rest of the site.

  1. Observe: record the element, selector, viewport width, and visible problem before editing.
  2. Predict: name the property you expect to fix it. If the issue is content, semantics, data loading, or JavaScript, say so.
  3. Repair: make the smallest useful change in the correct stylesheet or markup.
  4. Prove: test at 320px, 768px, and a wide desktop; test 200% zoom and keyboard navigation. Use Print Preview where relevant.
  5. Explain: write one sentence about why it worked. Remove temporary debugging styles and consolidate duplicate rules.

Hard mode: repeat one repair without looking at its solution. Design mode: give the same page a different mood by changing only typography, spacing, and tokens. Restraint mode: remove a decoration that doesn’t help a reader.

Finish when pages are easier to read and use, not when you have used every CSS feature. A page with missing content needs content; CSS should never invent research results, load-state messages, or essential labels.
