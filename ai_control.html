Can AI Control Keep Up with Frontier AI?

AI control means deploying a model you don't fully trust inside a protocol that should stop it from causing harm even if it tries: usually a weaker, trusted model monitors it, and suspicious actions are blocked or audited. This page models control as a capability on the same scale as the models themselves, a task length in hours, so that the gap between the two predicts how often an attacking model would be stopped.

How to read the chart
  • Blue dots are frontier models from all labs. Higher means more capable: the length of task (in expert-human time) the model completes half the time. Hollow dots are estimates for models METR hasn't measured.
  • The purple step line is the best control demonstrated so far: the most capable attacker whose attacks the best published protocol would stop with the chosen probability. It steps up whenever a new result beats the record. Models above the line are stopped less often than that; the further above, the less often.
  • Each square is one evaluation's result, converted to the same scale. Filled squares use the paper's strongest attacker. Green rings are monitors AI companies ship; a company's test of its own monitor (dashed ring) can't set the record.
  • The lower panel turns the gap into a probability: the modelled share of the most capable model's attacks that control of the time would stop, against the chosen target.

What the model says

  • Smarter attackers break the protocols. Prompt-injecting the monitor (78→12%), choosing when to attack (36→9%), simulating the monitor (89→17%) and colluding monitors (81→44%) all cut safety sharply, which is why control looks much weaker against the strongest attacks. Most evaluations don't test these attacks at all.
  • Shipped monitors look much better in their makers' own tests. OpenAI reports its Codex auto-review monitor catching 96.1% of covert attacks built from Claude Opus 4.5 trajectories. In an independent red-team in September 2026, the blocking monitors in Claude Code (Auto Mode) and OpenAI Codex (Guardian) stopped only 35% and 28% of attacks by a persistent Claude Opus 5 agent; a hardened research version stopped 91%. The tests differ in attacker, persistence and knowledge of the monitor, which is exactly what makes the gap large.
  • The result is fragile. Fewer than twenty results from nine papers, with different tasks, metrics and attack effort. The record rests on a handful of them; read it as a summary of published evidence, not a measurement.

How the model is built

Model. The share of attacks stopped is sigmoid(K · ln(C / A)), where A is the attacker's capability and C is control capability, both as METR-style task lengths. Each protocol gets one C, fitted to all the attackers it was tested against (for a single attacker, C = A · exp(logit(share stopped) / K)). Control capability at a date is the highest C of any protocol published by then: the best control anyone has demonstrated, not an average. The chart shows the attacker capability stopped with probability P, which is C · exp(−logit(P) / K): at 95%, that is C divided by about 135.

Judgement calls: (1) Slope K = 0.6. Taken from LinuxArena, the one independent evaluation that runs many attackers (seven, from four labs) against the same monitor and protocol. With K = 0.6, a tenfold capability gap moves the share stopped from 50% to 20% or 80%. At the 95% level, results near 95% sit close to their attacker's own capability, so K matters little there; it matters more when converting results far from the chosen level. (2) Best protocol, not average. Different protocols are tested at the same time, and the weaker ones say little about what control can do. One protocol tested against several attackers gets one capability, so a single easy attacker can't inflate it (in LinuxArena, Gemini 3 Flash's 97% would otherwise set the record). The record uses research protocols and independent tests of production monitors; companies' tests of their own monitors are shown but can't set it. A protocol stays the record until beaten, so the line is only as reliable as the result behind it: hover over a step to see which one. In the "strongest attacks" view, protocols that were never tested against a stronger attacker keep their headline result. (3) Ordinary vs strongest attacks. "Ordinary" uses each paper's headline result. "Strongest" swaps in the result against the paper's strongest attacker where one exists. The default view is the demanding one: 95% of attacks stopped, against the strongest attacks. (4) Capability scale. Models METR has measured use METR's 50% time horizon (v1.1). Others are placed using Epoch AI's Capabilities Index (ECI), converted with a log-linear fit across the 21 models with both measurements: ln(minutes) = -18.25 + 0.157 × ECI (R² = 0.97, typical error ×1.4). After METR's last measurement (April 2026), the frontier is each model that set a new ECI high. (5) One result per evaluation and attacker, using the paper's best protocol at roughly normal usefulness and its own safety metric (safety, catch rate, or attacks blocked), which aren't strictly comparable. LinuxArena's per-attacker results are 100% minus the "successful sabotage" rate. Shares are clipped to 1-99% when converting to an implied capability. (6) Only adversarial evaluations are included, where the model is told to evade the monitor. Models missing from Epoch's index (Grok 4.1, MiMo-V2-Flash) aren't placed.
